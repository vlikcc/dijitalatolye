# DijitalAtölye
Turkish educational game library for students and teachers. Web platform rebuilt in Next.js/React/TypeScript, PostgreSQL/Drizzle, Better Auth, Tailwind/shadcn. Single Linux pilot deployed with Dokploy. Anonymous visitors find games by grade/subject/outcome and play; verified teachers upload self-contained HTML/ZIP; editors review immutable scanned versions before publishing. No live-data migration. Student accounts, class membership, assignments and version-pinned game checkpoints are available behind STUDENT_LEARNING_ENABLED (default false). No social features or AI game generation.

Brand commitments: the approved name is Dijital Oyun Atölyesi. Preserve the supplied four-part circular puzzle logo and its approved once-per-document line-to-colour signature. The approved world is Keşif Atlası: one neutral ground, navy text/actions and white controls across public discovery, game detail/player chrome, shared account screens and all role workspaces. Subject colours, original game artwork and game-internal styling remain intact. The local CC0 paper texture is limited to discovery, game detail and account introductions; workspaces stay flat and the footer is a short light closure. Locally served Manrope headings and brand lettering pair with Source Sans 3 UI. Light theme for classrooms and home study. Search/filter/play leads, teacher upload is secondary. Real game screenshots and recorded asset provenance; no invented metrics. Approved code-led implementation. Existing Angular/.NET sibling files remain untouched.

Account and role contract: `/giris` is the shared email-or-student-username entry. `/kayit` offers teacher/student tabs when student learning is enabled; the student tab is `/kayit?tur=ogrenci`. Legacy student login/registration URLs redirect to these shared routes. Login, verification and recovery preserve the requested next destination; `/oturum` checks the authenticated role and accepts only a safe local destination allowed for that role, otherwise using its workspace home. Teachers require email verification; Yönetici and Admin also require 2FA. Student registration collects no email. Role identifiers in storage and APIs remain unchanged: `student` = Öğrenci (assignments, saved game progress, classes, account); `teacher` = Öğretmen (owned content, classes, assignments, reports and assigned recovery); `editor` = Yönetici (teacher capabilities plus editorial review, including an explicit compliant self-publication decision); `admin` = Admin (users, definitions, system operations, logs, inspection, recovery takeover and unpublishing). Admin cannot create or edit game content, teach, assign or approve publication. Navigation, page guards and APIs share the central capability policy; object ownership is checked separately.

Workspace tasks use selected sections rather than a single long dashboard. Review and registration panels remain mounted to preserve draft inputs. Admin lists query selected data with server-side search and pagination. The global extension changes neither the production default `STUDENT_LEARNING_ENABLED=false` nor stored role ownership; it includes no production migration or deployment. Current implementation and bounded verification are recorded in `docs/UNIFIED-EXPERIENCE.md`.

October 2026 demo: two public screen types, discovery and combined game detail/player; 16 clearly labelled, bundled playable examples for grades 3–8. Bookmarks are local to this browser and site origin for both visitors and signed-in users, accessible through Kaydettiklerim; they do not sync to an account. Share public game links by copying, opening a WhatsApp/email composer, or the device share sheet when supported; the user chooses the recipient and sends. Teacher guidance accompanies games. Bundled demos remain anonymous examples; student tracking and homework use published SDK-compatible packages. Bundled demos are explicitly enabled with DEMO_CATALOG_ENABLED=true and never impersonate scanner-approved teacher uploads. Existing uploaded games retain their separate origins and moderation pipeline.

Primary tasks: students discover, play and save games at home or in class; teachers find classroom material; upload and track revision; inspect scanner results, static extraction evidence, curriculum sources and preview; make explicit publication decision. Fail closed on scanner failure. No AI provider or AI evaluation stage. Teachers confirm extracted metadata; editors verify curriculum sources separately from educational suitability. Curriculum data is partial and source uncertainty stays visible. Games may publish without a curriculum claim. User game origins separate from application and from other versions.

Technical review extension: uploaded games have version-bound static reports and a required human editorial checklist. Accessibility findings are warnings with explicit dispositions; safety blocks cannot be overridden. A teacher/package raster cover takes precedence; otherwise a clearly identified typographic information cover uses existing subject colours and local fonts. No browser executes uploaded code for cover generation. Submitted metadata and covers are frozen together; later cover changes create a fresh review version.

Public audience entry: the guest header and footer use “Nasıl kullanılır?” at `/nasil-kullanilir`, with distinct student discovery/account and teacher contribution paths. `/ogretmenler-icin` redirects there. Student account links respect the existing learning flag; anonymous play and browser-local bookmarks need no account. The catalog and shared account introduction address both classroom and home learning.
